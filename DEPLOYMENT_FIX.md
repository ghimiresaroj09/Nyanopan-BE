# Deployment Fix for Render "Unknown command: collectstatic" Error

## Problem Summary
Your Django ecommerce application was failing to deploy on Render with the error:
```
Unknown command: 'collectstatic'
Type 'manage.py help' for usage.
```

## Root Cause
The error occurred because the `python` command used in the build script might not have been using the correct Python interpreter from Render's virtual environment (`.venv`), causing Django and its installed apps not to be available when running management commands.

## Changes Made

### 1. Updated `build.sh`
**File: `build.sh`**

Changes:
- Changed `pip install` to `python -m pip install` to ensure we use pip from the correct Python interpreter
- Added comprehensive diagnostic output to help debug issues:
  - Python version and executable path
  - Virtual environment status
  - Django installation verification
  - Settings module verification
  - List of available management commands
- Added explicit environment variable display

### 2. Enhanced `config/settings/production.py`
**File: `config/settings/production.py`**

Changes:
- Added try-except block around settings import with detailed error logging
- This will help identify if there are any import errors when loading settings

## What These Changes Do

1. **Ensures correct Python interpreter**: Using `python -m pip` instead of just `pip` ensures we're using the pip module from the same Python interpreter that will run Django commands.

2. **Provides diagnostic information**: The enhanced build script now outputs:
   - Which Python version is being used
   - Whether a virtual environment is active
   - Whether Django is properly installed
   - Whether settings are loading correctly
   - Whether `django.contrib.staticfiles` is in INSTALLED_APPS
   - What management commands are available

3. **Better error messages**: If settings fail to load, you'll now see exactly what went wrong instead of a generic "Unknown command" error.

## Environment Variables Required on Render
Make sure these are set in your Render service environment:
- `DJANGO_SETTINGS_MODULE=config.settings.production` (already in render.yaml)
- `SECRET_KEY` (should be auto-generated by Render)
- `DATABASE_URL` (your Neon pooled connection string)
- `DATABASE_URL_UNPOOLED` (your Neon direct connection string)
- Other variables as per your `.env.example`

## Why This Should Work

The original build script used bare `pip install` which might have been using a system pip rather than the virtual environment's pip. By using `python -m pip install`, we ensure that:

1. The same Python interpreter that will run `manage.py` is used to install packages
2. Packages are installed in the correct virtual environment
3. Django and all its management commands will be available when we run `manage.py collectstatic`

## Additional Notes

### Python Version
Your `render.yaml` specifies Python 3.13.14, but the build log shows it's using 3.13.15. This is fine - Render uses the `.python-version` file (which contains `3.13.15`) over the render.yaml setting.

### Collectstatic is Available Locally
We verified that `collectstatic` works perfectly on your local machine with production settings, so the issue is definitely environment-specific to Render.
